What it does

Built for engagement fieldwork.

AEOS helps the auditor execute the approved program. It does not invent scope, criteria or procedures that are missing from the source.

01

Run the work

Turn approved procedures into structured TOD and TOE workpapers, meeting plans, evidence requests and progress updates.

  • Work-program intake
  • Walkthrough preparation
  • Procedure execution
02

Keep the trail

Preserve the link between source, procedure, evidence, result and conclusion throughout the engagement.

  • Source provenance
  • Evidence state
  • Visible gaps and contradictions
03

Review the result

Separate drafting from reliance. Corrections, exceptions and final decisions remain with the auditor.

  • Independent QC
  • Auditor checkpoints
  • Controlled merge and reporting

Capabilities

One system across fieldwork.

Start

Engagement setup and intake

  • Create the engagement record and source register.
  • Set criteria, file permissions and working folders.
  • Convert an approved spreadsheet AWP into a reviewable Markdown working copy when useful.
Week 1

Planning, walkthroughs and meetings

  • Build the TOD plan for each approved AWP group.
  • Prepare agendas, interview questions and evidence requests.
  • Create factual minutes while keeping auditor analysis separate.
Evidence

Evidence handling and Test of Design

  • Register originals and working copies with provenance and state.
  • Link each source to the relevant request or procedure.
  • Run authorized TOD procedures and record missing or contradictory evidence.
Testing

Population, sampling and TOE

  • Prepare population and completeness records for approval.
  • Record the approved sampling method, selected items and attributes.
  • Run TOE item by item and retain every expected evidence-result pair.
Week 2

Follow-up, refresh and quality review

  • Carry unresolved TOD work and RFIs into Week 2.
  • Process new evidence and refresh TOD through its own review route.
  • Review TOD and TOE separately before merge.
Finish

Reporting, closure and learning

  • Merge reviewed TOD and TOE into the final workpaper.
  • Prepare progress, reporting and closure drafts.
  • Record reusable engagement learning after auditor approval.

Configurable by design

Configure the engagement workflow, not the control boundary.

AEOS's agentic and modular design lets an audit function align the workspace to its approved lifecycle, roles, criteria, templates and terminology without forcing every engagement into one fixed format.

Core

Reusable foundation

The lifecycle structure, agent profiles, workflow skills, prompts, templates, evidence controls and operating guides form a readable modular core.

Workflow

Composable engagement routes

Skills can define the required inputs, stage order, human checkpoints, stop conditions and outputs for the organization's approved engagement process.

Overlay

Local methodology and templates

A private overlay can supply approved criteria, playbooks, templates, terminology and restricted examples while keeping engagement material outside the reusable public core.

Boundary

Controls remain visible

Configuration may change the local route, but source authority, provenance, draft state, file boundaries, human approval and independent review stay explicit.

LLM contract

Choose the model for the job.

AEOS does not bind the workspace to one model. The auditor chooses an approved route for each task based on capability, data sensitivity and organizational authorization.

Capability
Read long documents, preserve source links, write structured Markdown and use the tools required by the workflow.
Enterprise tenant
Copilot-hosted models may support sensitive work only when the specific provider, use case, tenant isolation or private tenancy, data handling and tool permissions are approved.
Local inference
Ollama keeps inference on the auditor's machine and can support restricted work when the hardware can run the selected model with sufficient context and operating headroom.
Remote cloud
Ollama Cloud provides access to larger hosted models and may suit lower-sensitivity data after provider and use-case approval. It remains remote processing.
ZDR boundary
Zero Data Retention reduces retention exposure. It is not equivalent to local processing, tenant isolation or private tenancy, and does not itself authorize restricted evidence to leave the enterprise boundary.
Data boundary
Restricted evidence stays off remote services unless that provider and use case are approved.
Runtime record
Record the agent, model ID, provider, source set and output location for each AEOS task.
Output rules
Cite sources, show gaps and contradictions, leave unsupported fields blank and route every output to the auditor.
Authority
The model may interpret, compare, draft and run bounded procedures. It cannot approve samples, exceptions, conclusions or communication.

Common questions

How AEOS is meant to be used.

Where does AEOS start?
With an approved audit work program. Planning decisions that are missing from the source remain open for the auditor.
Does AEOS replace the auditor?
No. The model can prepare, compare, test and draft. The auditor owns evidence sufficiency, exceptions, conclusions and communication.
Do all source documents need to be Markdown?
No. Source files can remain in their original format. AEOS uses Markdown for its working context and audit outputs.
Does AEOS require one specific model?
No. The workspace is model-independent. The selected model and provider must suit the task and evidence boundary.
What happens to restricted evidence?
It can use a remote route only when the provider and use case are approved. Otherwise the auditor selects an approved local route.
